# Анализатор конфигурационных файлов

## Описание

Эта программа на основе входных файлов (`impulse_test_input.xml`, `config.json`, 
`patched_config.json`) генерирует 4 выходных файла.

### Анализ xml-файла с описанием классов

Программа парсит XML-файл, содержащий описание классов и их атрибутов, и генерирует:
1. файл `config.xml`, который представляет собой пример внутренней конфигурации базовой станции, соответствующий 
представленной модели;
2. файл `meta.json`, который содержит мета-информацию о классах и их атрибутах. Фронтенд использует данный файл для 
корректного отображения дерева объектов в интерфейсе пользователя (UI).

### Анализ 2 конфигурационных файлов и создание файла `delta.json`

Программа генерирует файл `delta.json` содержит в себе дельту, отражающую разницу между файлами `config.json` и
`patched_config.json`. Имеет в себе поля:  
`additions` — новые поля, которые есть в patched_config.json, но отсутствуют в config.json;  
`deletions` — удаленные параметры. Имеются в config.json, но отсутствуют в patched_config.json;  
`updates` — поля, значения которых были изменены.

### Анализ конфигурационного файла и дельты

Программа генерирует файл `res_patched_config.json`, который содержит в себе результат применения полученной дельты 
(`delta.json`) к файлу `config.json`. Значения в `res_patched_config.json` совпадают со значениями в
`patched_config.json`.

В коде используются модули стандартной библиотеки: `json`, `os`, `re`, `sys`, `xml.etree.ElementTree`,
`collections.deque`, `xml.dom.minidom`, `typing`.

## Использование

Программа запускается из корня проекта без параметров. По умолчанию программа ищет входные файлы в директории
`test_files`, а выходные файлы генерируются в директории `out`, которая при отсутствии создаётся.
При надобности путь к входной и выходной директориям можно поменять в файле `.env`.

## Обработка ошибок

Программа проверяет  

в XML:
- Корректность XML-файла (`validate_xml`),
- Наличие файла,
- Наличие корневого класса (ровно один `isRoot="true"`),
- Существование всех классов в `Aggregation`;

в JSON:
- Корректность json-файлов (`load_and_validate_json`),
- Наличие файлов,
- Структуру входных файлов.

При ошибках программа выводит сообщение и завершает работу с кодом 1.

## Тестирование

Для проверки корректности работы предусмотрены тесты, написанные с использованием `pytest`, включая:

- Позитивные и негативные сценарии генерации и применения дельт;
- Позитивные и негативные для анализа XML;
- Тесты на функцию-утилиту для генерации уникального имени файла.
